# IrForge Pay Agent (اندروید + iOS)

اپِ گوشیِ صاحبِ کارت که پیامکِ بانک را به وبهوکِ کانالِ پرداختِ IrForge می‌فرستد (جایگزینِ MacroDroid)،
طوری که با **تغییرِ IP، قطع/وصلِ VPN و قطعیِ اینترنت** چیزی گم نشود.

## چه چیزی را حل می‌کند
| مشکلِ MacroDroid | راهِ حل در این اپ |
|---|---|
| یک POST ساده؛ اگر همان لحظه VPN قطع بود، پیامک برای همیشه گم می‌شد | هر پیامک اول در **صفِ ماندگارِ SQLite** ذخیره می‌شود، بعد با WorkManager (محدودیتِ «اینترنت دارم» + backoff ۱۰ثانیه‌ای) ارسال می‌شود؛ بعد از ری‌استارتِ گوشی هم ادامه دارد |
| دامنه فقط از یک مسیر (با VPN یا بی‌VPN) باز است | هر ارسال روی **همه‌ی شبکه‌های موجود** (فعلی، Wi-Fi، موبایل، VPN/بی‌VPN) و **همه‌ی آدرس‌ها** (اصلی + پشتیبان) امتحان می‌شود |
| ارسالِ تکراری خطرناک است | سرور با `content_hash` idempotent است؛ retry امن است |
| ۴۰۱/۴۰۳ (کلید عوض شده) بی‌صدا گم می‌شد | پیامک‌ها «متوقف» می‌مانند، نوتیفیکیشن می‌آید، و با اصلاحِ کلید خودکار ارسال می‌شوند |
| تنظیمِ سخت | اسکنِ QR از پنل، یا کپیِ لینک، یا ورودِ دستی؛ تستِ اتصال و چک‌لیستِ باتری/مجوز با دکمه |
| پیامکِ شخصی ممکن بود لو برود | فقط فرستنده‌های مجازِ بانک ارسال می‌شوند؛ متنِ پیامکِ ارسال‌شده از صف پاک می‌شود |

## iOS — محدودیتِ خودِ اپل
iOS به هیچ اپی اجازه‌ی خواندنِ پیامکِ دریافتی نمی‌دهد. پس روی آیفون اپ فقط **تنظیمات، تستِ اتصال و راهنمای «Shortcuts ← Automation ← Message»**
(با مقادیرِ آمادهٔ کپی) را می‌دهد، و آن اتوماسیون retry ندارد. برای پایداریِ واقعی، گوشیِ دریافتِ پیامک باید **اندروید** باشد.

## ساخت
پیش‌نیاز: Flutter ≥ 3.22 (و برای iOS یک Mac + Xcode).
```bash
cd mobile
./bootstrap.sh          # flutter create + اعمالِ کدِ native (overlay/) + وابستگی‌ها
flutter run             # یا:  flutter build apk --release   |   flutter build ipa
```
`android/` و `ios/` تولیدی‌اند (gitignore)؛ منبعِ کدِ native در `overlay/android/` است.

## اتصال
پنل ← کارت‌به‌کارت خودکار ← ساختِ کانال/چرخشِ کلید ← در دیالوگِ کلید یک **QR** است ← در اپ «اتصال با اسکن QR».
لینکِ QR: `irforge-pay://setup?u=<webhook>&u=<پشتیبان>&s=<کلید>&b=<فرستنده‌ها>` (حاویِ کلید است؛ منتشرش نکنید).
آدرسِ پشتیبان (مثلاً دامنه‌ی دوم) را می‌توان در «ورودِ دستی» اضافه کرد.

## وضعیتِ راستی‌آزمایی
- Dart: `flutter analyze` بدونِ خطا، `flutter test` سبز (پارسِ لینک).
- Kotlin و اجرای روی دستگاه در محیطِ ساخت **کامپایل/تست نشده** (Android SDK نبود)؛ قبل از فروش روی یک گوشیِ واقعی تست کنید:
  پیامکِ بانک با VPN روشن، خاموش، حالتِ هواپیما (باید بعد از وصل شدن برسد)، و ری‌استارتِ گوشی.

## تنظیمات و مدیریت داخلِ اپ
- **تنظیمات** (آیکن ⚙️): تلاشِ مجدد، مهلتِ پاسخ، امتحانِ همه‌ی شبکه‌ها، نگهداریِ سابقه، اعلان‌ها، بررسیِ آپدیت — همه با اسلایدر/سوییچ؛ هر تغییر همان لحظه ذخیره می‌شود.
- **صفِ پیامک‌ها** (آیکن 📋): هر پیامک با وضعیتش (در صف / ارسال شد / متوقف / ردشده)، ارسالِ مجدد و حذفِ تک‌تک یا «ارسالِ مجددِ همه».
- همان اولِ اجرا همه‌ی دسترسی‌ها (پیامک، اعلان، دوربین، معافیت از باتری) یک‌جا خواسته می‌شود.

## انتشارِ نسخه‌ی جدید (آپدیتِ داخلِ اپ، فقط اندروید)
یک‌بار: `./tools/make-keystore.sh` → سه secret در گیت‌هاب (`ANDROID_KEYSTORE_BASE64`، `ANDROID_KEYSTORE_PASSWORD`، `ANDROID_KEY_ALIAS`).
**فایلِ keystore را نگه دارید؛ با کلیدِ دیگر هیچ آپدیتی نصب نمی‌شود.**

هر نسخه:
1. Actions ← Build Android APK ← Run workflow. versionCode خودکار افزایش می‌یابد.
2. فایلِ `irforge-pay-agent.apk` را جایی با لینکِ مستقیمِ https آپلود کنید (سایت/CDN/استوریج).
3. در خلاصه‌ی همان اجرا چهار مقدار آمده؛ روی سرور بگذارید: `AGENT_VERSION_CODE`، `AGENT_VERSION_NAME`، `AGENT_APK_SHA256`، `AGENT_APK_URL` (اختیاری: `AGENT_NOTES`، `AGENT_MANDATORY=1`).
4. اپ‌ها هر چند ساعت `GET /api/agent/latest` را می‌خوانند ← نوتیف + کارتِ «نسخه‌ی جدید» ← «دانلود و نصب» (هش چک می‌شود؛ بار اولِ نصب باید «اجازه نصب از این منبع» روشن شود).
iOS آپدیتِ مستقیم ندارد (قانونِ اپل؛ از TestFlight/App Store).
